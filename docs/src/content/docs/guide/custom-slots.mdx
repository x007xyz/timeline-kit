`trackConfigs[type].clip` 和 `trackConfigs[type].icon` 支持两种写法：

- **简单工厂函数**：`clip: (ctx) => HTMLElement | string | null`（适合纯静态或轻量节点）。
- **生命周期对象（推荐）**：`clip: { mount(host, ctx) { return { update, destroy } } }`。

## 为什么推荐 `mount / update / destroy`？

在老版本或简单实现中，每次播放头跳转、选区变更或文本微调都会销毁并重建整个片段 DOM，导致以下问题：

1. 图片 `<img>` 闪烁或重复触发解码；
2. React / Vue 子组件丢失局部状态；
3. 视口虚拟化滚出屏幕时无法通知宿主释放资源。

采用生命周期协议后，`mount` 仅在片段进入视口时执行一次；后续选中态 (`ctx.isSelected`)、宽度 (`ctx.clipWidthPx`) 或业务属性变化时，只调用 `update(nextCtx)` 进行局部 DOM 更新：

```ts
import type { ClipRenderContext, SlotRendererObject } from 'timeline-kit'

export const fancyTextSlot: SlotRendererObject<ClipRenderContext> = {
  mount(host, ctx) {
    const root = document.createElement('div')
    const badge = document.createElement('span')
    const text = document.createElement('span')
    root.append(badge, text)

    const apply = (next: ClipRenderContext) => {
      const preset = String(next.clip.meta?.preset ?? 'neon')
      root.className = `tk-fancy-clip is-${preset}`
      badge.textContent = `花字 · ${preset}`
      text.textContent = next.clip.resource ?? next.clip.name
    }

    apply(ctx)
    host.replaceChildren(root)

    return {
      update(nextCtx) {
        apply(nextCtx) // 原地更新，零节点销毁重建
      },
      destroy() {
        host.replaceChildren()
      },
    }
  },
}
```
